# lottery-one-pick

每期**只出 1 注**的超级大乐透选号工具：在你自己排除过的号池里随机抽一注，再让它通过
「历史关 + 前区关 + 后区关」三道筛选。

*A one-ticket-per-draw picker for China's Super Lotto (大乐透): sample one ticket from your
filtered number pool, then validate it against 13 structural rules and a history-collision check.*

---

## 它做什么 / 不做什么

**做什么**

- 维护一份历史开奖数据表（体彩官方接口按期号增量补齐，自动修补表中间断档）
- 按你给的排除号收窄号池，在池内随机组 1 注，过不了三关就重抽
- 交付这一注并落盘存档（含出号记录，可复盘）
- 反向能力：拿任何一注号码去筛，告诉你过不过、不过是被哪条规则挡住的
- 开奖后对账：算出这一注中了几等奖、多少钱

**不做什么**

- 不做走势预测，不看"专家号"、不做频次加权、不做多注覆盖
- 一套流程固定就是 1 注，不因为"想提高覆盖面"而多加注
- 不自动下注、不接入任何投注平台

这套工具的定位是**形态过滤器**：把历史上罕见的号码形态（全奇/全偶、4 连以上、单区堆积、
和值极端…）从随机结果里剔掉。它不改变中奖概率，只是让随机结果落在一个你认可的形态空间里。

## 安装

需要 Python 3.8+（开发环境 3.11）。

```bash
pip install -r requirements.txt
```

唯一的第三方依赖是 `openpyxl`（读写 xlsx），其余全部是标准库。

## 三步上手

**① 更新数据表**（联网，从体彩官方接口补最新期）

```bash
python update_excel.py
```

仓库自带 `data/大乐透历史开奖数据.xlsx`（2926 期，07001 ~ 26108），clone 下来即可直接用。

**② 出这一期的一注**

```bash
python dlt_pick_one.py -ef 4,9,13 -eb 3,5
```

`-ef` / `-eb` 分别是前区、后区要排除的号，可多个，不传就是不排除。

```
========================================================================
出号 · 目标期 26109    （主开关 CURRENT_PERIOD = 26109）
========================================================================
  历史基准   : 2926 期，07001(2007-05-30) ~ 26108(2026-09-21)
  上期号     : 01 05 07 21 35  +  01 04
  前区排除   : 04 09 13    → 池 32 个号
  后区排除   : 03 05    → 池 10 个号
------------------------------------------------------------------------
  06 10 11 20 35 + 10 12
  和值82  跨度35-6=29  2奇3偶  区间3/1/1  最长2连  AC=6  后跨2
  ✅ 三关全过（13 条规则 + 历史杀号）　第 1 次尝试命中，用时 0.00s
------------------------------------------------------------------------
  已落盘: 我的_26109_1注.txt
  已记录: 出号记录.txt
========================================================================
```

**③ 开奖后对账**

```bash
python check_result.py "01 05 07 21 35 + 01 04" --file 我的_26109_1注.txt
```

## 命令速查

| 命令 | 作用 |
| --- | --- |
| `python update_excel.py` | 增量更新数据表（`--dry-run` 预览 / `--check` 自检 / `--no-fetch` 手工补录 / `--snapshot` 另存快照） |
| `python dlt_pick_one.py` | 出 1 注（`-ef` 前区排除 / `-eb` 后区排除 / `--seed` 复现 / `--period` 指定期号 / `--outdir` 落盘目录） |
| `python filter_check.py` | 筛号器：`python filter_check.py "08 09 10 11 25 + 04 12"`，或 `--file 注单.txt` 批量筛 |
| `python check_result.py "开奖号" --file 注单.txt` | 开奖对账（`--pool-big` 切换奖池 ≥8 亿的上浮口径） |
| `python show_period.py 26080 26076` | 按期号查历史开奖号 |
| `python -m unittest discover -s tests -v` | 跑单元测试 |

### 关于「主开关」

期号只在 `dlt_pick_one.py` 顶部写一次：

```python
CURRENT_PERIOD = "26109"   # ← 全项目唯一「主开关」
```

其余脚本（筛号器、对账）的默认期号都从这一行读，不用逐个改。它会按**文本正则**读取，
所以请保持 `CURRENT_PERIOD = "NNNNN"` 这个写法。

## 三道关是什么

判定第 N 期时，历史数据严格只取第 N 期**之前**的记录（不会用未来信息，测试里有专门一条守着）。

### 第一关 · 历史关（1 条）

撞历史开奖号的组合直接杀掉：

| 撞法 | 范围 |
| --- | --- |
| 前区中 5 个 | 全历史（2007 年至今）都杀 |
| 前区 4 个 + 后区 2 个 | 全历史都杀 |
| 前区 4 个 + 后区 0~1 个 | 只杀 2026 年以来的 |
| 前区 3 个 + 后区 2 个 | 只杀 2026 年以来的 |

### 第二关 · 前区关（10 条）

| # | 规则 | 阈值 |
| --- | --- | --- |
| ① | 奇偶 | 奇数 1~4 个（禁全奇、全偶） |
| ② | 区间分布 | 1-12 / 13-24 / 25-35 至少占 2 区，单区最多 4 个 |
| ③ | 连号 | 最长连号 ≤ 3 |
| ④ | 和值 | 40 ~ 150 |
| ⑤ | 跨度 | 最大 − 最小 ∈ 13 ~ 33 |
| ⑥ | 首尾 | 最小号 ≤ 20 且 最大号 ≥ 21 |
| ⑦ | 上期重号 | 与上期前区重合 ≤ 3 个 |
| ⑧ | 质数 | 质数个数 ≤ 4 |
| ⑨ | 012 路 | 5 个数不能同余（mod 3） |
| ⑩ | AC 值 | 互异差值个数 − 4 ≥ 2 |

### 第三关 · 后区关（2 条）

| # | 规则 | 阈值 |
| --- | --- | --- |
| ⑪ | 冷号 | 遗漏 ≥ 8 期的号最多 1 个 |
| ⑫ | 上期重号 | 与上期后区重合 ≤ 1 个 |

> 后区跨度规则（原 ≤7）已于 2026-09 整条取消：该阈值在全历史误杀 428 期（14.6%），
> 是全部规则里最狠的一条，而后区只有 66 种组合、大众选号接近均匀分布，砍掉 15% 换不来收益。

13 条规则 + 历史杀号**全部通过**才算过。每条的取舍依据、以及每条在全历史/近 50 期
分别筛掉了哪些期号，见 [`docs/rules.md`](docs/rules.md)。

## 数据表格式

`data/大乐透历史开奖数据.xlsx`，第一个工作表，第 1 行是表头，10 列：

| 列 | 内容 | 示例 |
| --- | --- | --- |
| A | 期号（5 位） | `26108` |
| B | 开奖日期 | `2026-09-21` |
| C~G | 前区 5 个号（升序） | `1` `5` `7` `21` `35` |
| H~I | 后区 2 个号（升序） | `1` `4` |
| J | 完整号码（展示用） | `01 05 07 21 35 01 04` |

表放在别处也行，按下面顺序第一个命中的会被采用：

1. 环境变量 `DLT_DATA` 指向的文件
2. `<仓库根>/data/大乐透历史开奖数据.xlsx`
3. `<当前工作目录>/大乐透历史开奖数据.xlsx`

```bash
# Windows
set DLT_DATA=D:\我的数据\开奖数据.xlsx
# macOS / Linux
export DLT_DATA=~/我的数据/开奖数据.xlsx
```

```
lottery-one-pick/
├── dlt_pick_one.py     # 主脚本：排除池随机 1 注 + 三关过筛（主开关宿主）

└── tests/test_rules.py # 单元测试（规则边界 + 端到端）
```

## 设计要点

**出号与筛号共用同一套判定**。主脚本的过筛不是自己再写一遍，而是直接调用
`filter_check.gates()`；筛号器内部还保留了"逐条规则镜像"用于报告是哪条挡住的，
并有一致性断言（drift）——一旦镜像和引擎口径分叉会当场告警，不会悄悄出两套结果。

**随机的正确性靠"抽到不过就重抽"**，而不是"先枚举全部合法组合再均匀抽"。两者分布等价，
前者实现简单且不必枚举 C(35,5)×C(12,2) 约 2100 万种组合。实测三关联合通过率约 78%，
一般 1~3 次就能命中；`--tries`（默认 50000）只是兜底。

**随机种子可控**。不传 `--seed` 是真随机；传了就固定种子，同一期重跑能复现同一注，
方便复盘"当时为什么是这一注"。

## 开发

```bash
python -m unittest discover -s tests -v
```

测试覆盖：奖金表全档位（奖池上浮/基准两档）、每条规则各一个只违反它的样本、
历史杀号的四种撞法、随机一注必过三关、以及"上下文不含目标期及之后数据"。

改规则请只改 `lottery_core.py` 里的判定函数，然后同步 `filter_check.py` 里用于展示的
`front_report()` / `back_report()` 镜像（两者不一致时运行时会有 drift 告警）。
